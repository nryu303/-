# 日本株分析システム — 画面デモ

J-Quants Premium の日本株データを蓄積し、条件抽出・バックテスト・PDF資料管理・実績記録を行う Web システムの **画面デモ(プロトタイプ)** です。

実際のデータベースや API には接続せず、画面構成と操作の流れをご確認いただくことを目的としています。

---

## このデモの目的

ご依頼いただいた要件を、文章ではなく**実際に触れる画面**としてお示しするものです。

- 「どんな画面で、どういう順番で操作するのか」
- 「どの要件が、どの画面に対応するのか」
- 「データがどこから来て、どこへ流れるのか」

上記を、開発着手前にすり合わせるためのものです。表示されている数値はすべてサンプルです。

---

## 操作の流れ

```
/  ファーストビュー  →  /login  ログイン  →  /dashboard  管理画面
```

1. **ファーストビュー(`/`)** — 全画面の映像の上に、システム名・概要・主な機能を表示します。「システムに入る」ボタン、Enter キー、右下の「スキップ」のいずれでもログイン画面へ進みます
2. **ログイン画面(`/login`)** — 左側は映像のみ、右側がログインフォームです。メールアドレスとパスワードを入力して「ログイン」を押します(デモでは入力があれば通過します)
3. **管理画面(`/dashboard` 以下)** — 以降は左サイドバーから各機能へ移動できます

未ログインの状態で管理画面のURLを直接開いた場合は、`/login` へ戻ります。
ログアウトするとファーストビュー(`/`)へ戻ります。

## イントロ動画の差し替え方法

初期状態では、コードで描画した背景(東京の夜景・桜・ローソク足・株価ティッカー)が表示されます。
動画に差し替える場合は、以下の手順で設置してください。

1. 商用利用可能な動画を用意します
   - [Pexels](https://www.pexels.com/ja-jp/search/videos/tokyo/) — 「日本」「東京」などで検索
   - [Pixabay](https://pixabay.com/ja/videos/search/japan/)
   - いずれも無料・帰属表示不要です(利用時に各サイトのライセンスをご確認ください)
2. ダウンロードしたファイルを **`public/intro.mp4`** という名前で配置します
3. ページを再読み込みすると、自動的に動画が再生されます

動画がない場合・読み込みに失敗した場合は、自動的に背景アニメーションに切り替わるため、
**動画を置かなくても画面は完成した状態で表示されます**。

推奨仕様: MP4 (H.264) / 1920×1080 / 10〜20秒 / 10MB以下

## 実際に動く部分 / 表示のみの部分

デモの性質上、動作する範囲を明確にしています。

### 実際に動作します

- **CSV出力** — 銘柄抽出・バックテスト・取引明細・実績記録の各画面で、**実際にCSVファイルがダウンロードされます**(Excelで文字化けしないBOM付きUTF-8)
- **銘柄抽出画面のフィルタ** — 市場区分・業種・時価総額・PBR・営業日数・キーワードによる絞り込みが、サンプル50銘柄に対して実際に適用され、件数と一覧が変化します
- **銘柄抽出画面の並び替え** — 見出しをクリックすると昇順・降順が切り替わります
- **バックテスト画面の保有期間切り替え** — 表の行をクリックすると、上部のサマリー指標が連動して切り替わります
- **バックテストの実行ボタン** — 進捗バーが進み、完了後に結果とトースト通知が表示されます(計算は行わず、サンプル結果を表示)
- **データ更新画面の再取得ボタン** — 進捗バーが進みながら「エラー → 実行中 → 成功」へ遷移します。「未完了のジョブを再実行」は複数ジョブを順番に処理します
- **画面検索(⌘K)** — 画面名・要件番号でインクリメンタル検索し、Enterで移動します
- **通知メニュー** — 未解決エラーの件数がバッジ表示され、クリックで該当画面へ移動します
- **サイドバーの折りたたみ** — 作業領域を広げられます
- **ログイン / ログアウト** — セッション状態を保持し、未ログインで管理画面を開くとログイン画面へ戻ります
- **PDF資料管理の一覧選択** — 行をクリックすると右側の抽出結果パネルが切り替わります
- **外部連携APIのエンドポイント選択** — 選択に応じてサンプルレスポンス(JSON)が切り替わります
- **画面遷移・レスポンシブ表示** — スマートフォンでのサイドバー開閉を含む全画面

### 表示のみです(保存・通信は行いません)

- ログイン認証(入力があれば通過します。実際の認証は行いません)
- PDF のアップロード・表示
- 各種フォームの保存ボタン(押すと通知は出ますが、保存はされません)
- APIキーの発行・無効化
- データはページを再読み込みすると初期状態に戻ります

## 技術構成(このデモ)

- **Next.js 15**(App Router)
- **React 19**
- **TypeScript**
- **Tailwind CSS**

外部ライブラリへの依存を最小限にするため、グラフ・図表はすべて SVG / CSS で描画しています。

### 本番システムで想定する構成

| 層 | 技術 |
|----|------|
| フロントエンド | Next.js + TypeScript + Tailwind CSS |
| バックエンドAPI | Python + FastAPI |
| データベース | Supabase Pro (PostgreSQL 15+) |
| ストレージ | Supabase Storage(PDF格納) |
| 認証 | Supabase Auth |
| バッチ処理 | Python (asyncio + httpx) / GitHub Actions |
| 監視 | Sentry + Supabase Logs |

## ディレクトリ構成

```
.
├── public/
│   ├── 分析ロゴ.png                サイドバー・ログイン画面のロゴ
│   └── intro.mp4               イントロ動画(任意 / 無い場合は背景アニメーション)
├── app/
│   ├── layout.tsx              ルートレイアウト
│   ├── globals.css             全体スタイル
│   ├── page.tsx                ファーストビュー(/)
│   ├── login/                  ログイン画面(/login)
│   └── (admin)/                管理画面(共通サイドバー適用)
│       ├── layout.tsx
│       ├── dashboard/          ダッシュボード      ← 第1段階(MVP)
│       ├── data-update/        データ更新          ← 第1段階(MVP)
│       ├── screening/          銘柄抽出            ← 第1段階(MVP)
│       ├── backtest/           バックテスト        ← 第2段階
│       ├── records/            実績記録            ← 第2段階
│       ├── documents/          PDF資料管理        ← 第3段階
│       ├── api-access/         外部連携API        ← 第3段階
│       └── architecture/       システム構成図
├── components/
│   ├── app-shell.tsx           サイドバー・上部バー・検索パレット
│   ├── intro-screen.tsx        ファーストビュー(動画 / フォールバック切替)
│   ├── logo.tsx                ロゴ表示(2倍拡大＋中央80%トリミング)
│   ├── intro-scene.tsx         背景アニメーション(CSS・SVGのみ)
│   ├── nav-items.ts            ナビゲーション定義(要件番号・開発段階)
│   ├── toast.tsx               トースト通知
│   └── ui.tsx                  共通UIパーツ
└── lib/
    ├── types.ts                型定義(本番のテーブル定義に対応)
    ├── mock-data.ts            サンプルデータ
    ├── session.ts              簡易セッション管理(本番は Supabase Auth)
    └── csv.ts                  CSV出力
```

本番実装では `lib/mock-data.ts` が Supabase へのクエリに置き換わり、
`lib/types.ts` の型定義がそのままテーブル定義と対応します。
`lib/session.ts` は Supabase Auth のセッション管理に置き換わります。
